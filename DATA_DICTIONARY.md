# AgentIQ Datathon — Data Dictionary

## Project

**Track:** AgriTech — Mandi-to-Market Supply Chain Optimizer
**Purpose:** Describe the fields used in the cleaned datasets for mandi arrivals, prices, MSP, weather, and transport logistics.

> **Important:** The files in `data/raw/` are the original input data. The files in `data/cleaned/` are generated by the cleaning pipeline. Missing values are retained where the original data does not provide enough information. Missing values are not replaced with invented values.

---

## 1. `mandi_master_cleaned.csv`

Contains the master information for monitored mandis.

| Column             | Description                                              | Data type |
| ------------------ | -------------------------------------------------------- | --------- |
| `mandi_id`         | Unique identifier of the mandi.                          | String    |
| `mandi_name`       | Name of the mandi.                                       | String    |
| `district`         | District associated with the mandi.                      | String    |
| `state`            | State associated with the mandi.                         | String    |
| `mandi_type`       | Type or category of mandi.                               | String    |
| `total_area_acres` | Total area associated with the mandi, measured in acres. | Numeric   |

## 2. `mandi_arrivals_cleaned.csv`

Contains crop arrival quantities reported at mandis.

| Column                 | Description                                                                                                                                                                                 | Data type |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| `arrival_id`           | Unique identifier for an arrival record.                                                                                                                                                    | String    |
| `date`                 | Date of the crop arrival.                                                                                                                                                                   | Date      |
| `mandi_id`             | Identifier of the mandi where the arrival was recorded.                                                                                                                                     | String    |
| `crop_name`            | Name of the crop.                                                                                                                                                                           | String    |
| `variety`              | Crop variety, when available.                                                                                                                                                               | String    |
| `arrival_quantity`     | Original reported arrival quantity.                                                                                                                                                         | Numeric   |
| `unit`                 | Original unit reported for the arrival quantity.                                                                                                                                            | String    |
| `farmer_count`         | Number of farmers associated with the arrival record, when available.                                                                                                                       | Numeric   |
| `unit_clean`           | Standardized unit used during cleaning.                                                                                                                                                     | String    |
| `arrival_quantity_qtl` | Arrival quantity converted to quintals. Kilograms are converted using 100 kg = 1 quintal, and tonnes using 1 tonne = 10 quintals.                                                           | Numeric   |
| `quality_flag`         | Data-quality status. `valid` indicates no detected negative-quantity issue; `invalid_negative_quantity` indicates a negative quantity was detected and removed from the converted quantity. | String    |

### Arrival quantity notes

* Negative arrival quantities are treated as invalid.
* Negative quantities are set to missing in `arrival_quantity_qtl`.
* Unknown or missing units may prevent conversion to quintals.
* Original columns are retained for traceability.

## 3. `price_and_msp_cleaned.csv`

Contains mandi prices and Minimum Support Price information.

| Column        | Description                                                  | Data type |
| ------------- | ------------------------------------------------------------ | --------- |
| `record_id`   | Unique identifier for a price record.                        | String    |
| `date`        | Date of the price observation.                               | Date      |
| `mandi_id`    | Identifier of the mandi.                                     | String    |
| `district`    | District associated with the price record.                   | String    |
| `crop_name`   | Name of the crop.                                            | String    |
| `min_price`   | Minimum reported price.                                      | Numeric   |
| `max_price`   | Maximum reported price.                                      | Numeric   |
| `modal_price` | Modal or most commonly reported price.                       | Numeric   |
| `msp`         | Minimum Support Price recorded for the crop and observation. | Numeric   |

### Price and MSP notes

* Some price and MSP fields are missing in the source data.
* Missing prices or MSP values are retained as missing rather than being invented.
* MSP risk analysis should use records where both the modal price and MSP are available.
* A record is considered below MSP when the modal price is lower than the corresponding MSP.

## 4. `weather_cleaned.csv`

Contains weather and rainfall observations.

| Column             | Description                               | Data type         |
| ------------------ | ----------------------------------------- | ----------------- |
| `sensor_id`        | Identifier of the weather sensor.         | String            |
| `timestamp`        | Original weather observation timestamp.   | Date/time         |
| `temperature`      | Original reported temperature.            | Numeric or String |
| `temp_unit`        | Original temperature unit.                | String            |
| `rainfall`         | Original reported rainfall value.         | Numeric or String |
| `rain_unit`        | Original rainfall unit.                   | String            |
| `humidity_percent` | Relative humidity percentage.             | Numeric           |
| `timestamp_ist`    | Standardized timestamp used for analysis. | Date/time         |
| `temperature_c`    | Temperature converted to Celsius.         | Numeric           |
| `rainfall_mm`      | Rainfall converted to millimetres.        | Numeric           |

### Weather notes

* Temperature values are converted to Celsius where the source value and unit can be interpreted.
* Rainfall values are converted to millimetres where the source value and unit can be interpreted.
* Missing timestamps remain missing when they cannot be parsed.
* Missing temperature or rainfall values remain missing when no reliable source value is available.
* Missing weather values should not be interpreted as zero rainfall or zero temperature.

## 5. `transport_cleaned.csv`

Contains transport and mandi-to-warehouse logistics records.

| Column                  | Description                                                                                                                                                       | Data type |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| `trip_id`               | Unique identifier for a transport trip.                                                                                                                           | String    |
| `mandi_id`              | Identifier of the source mandi.                                                                                                                                   | String    |
| `destination_warehouse` | Destination warehouse for the trip.                                                                                                                               | String    |
| `departure_time`        | Original departure timestamp.                                                                                                                                     | Date/time |
| `arrival_time`          | Original arrival timestamp.                                                                                                                                       | Date/time |
| `transit_hours`         | Transit duration in hours.                                                                                                                                        | Numeric   |
| `distance`              | Original reported travel distance.                                                                                                                                | Numeric   |
| `distance_unit`         | Original distance unit.                                                                                                                                           | String    |
| `vehicle_no`            | Original vehicle registration value.                                                                                                                              | String    |
| `driver_id`             | Driver identifier, when available.                                                                                                                                | String    |
| `departure_time_clean`  | Standardized departure timestamp.                                                                                                                                 | Date/time |
| `arrival_time_clean`    | Standardized arrival timestamp.                                                                                                                                   | Date/time |
| `distance_km`           | Distance converted to kilometres.                                                                                                                                 | Numeric   |
| `quality_flag`          | Data-quality status. `valid` = no issue detected; `invalid_negative_transit` = a negative transit time was detected and nulled; `invalid_unrealistic_transit` = transit time exceeded 168 hours and was nulled. | String    |
| `vehicle_no_clean`      | Standardized vehicle registration value.                                                                                                                          | String    |

### Transport notes

* Negative transit times are treated as invalid.
* Negative transit times are set to missing.
* Transit time may be calculated from cleaned arrival and departure timestamps when the original transit value is missing.
* Distance is converted to kilometres when the source unit is recognized.
* Missing or unrecognized distance units may result in missing `distance_km`.
* The current cleaning threshold treats transit times above 168 hours as unrealistic.
* Transit times exceeding 168 hours are treated as unrealistic and set to missing.

## Data-quality summary

The cleaning pipeline performs the following operations:

* Standardizes mandi IDs and crop names.
* Converts numeric and currency-formatted values into numeric form.
* Converts arrival quantities into quintals.
* Flags negative arrival quantities.
* Converts temperature values into Celsius where possible.
* Converts rainfall values into millimetres where possible.
* Parses and standardizes timestamps.
* Converts distances into kilometres where the unit is recognized.
* Calculates missing transit durations from timestamps where possible.
* Flags negative transit durations.
* Retains missing values when the source data does not contain enough reliable information.
